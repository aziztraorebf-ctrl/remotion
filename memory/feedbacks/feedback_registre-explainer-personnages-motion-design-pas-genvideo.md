Avant de choisir un outil de generation pour une scene a personnages/decors dans un registre
"explainer" (pub SaaS, motion design corporate, style Fiverr/portfolio freelance classique),
identifier D'ABORD le registre visuel cible — il determine la FAMILLE d'outil, pas seulement
le prompt.

**Pourquoi** : discussion de fin de session sur le test MOCH-IT (2026-08-09), hors production.
Observation : les videos "explainer" a personnages/decors de ce registre (portfolio Fiverr
observe en reference) sont faites en motion design vectoriel classique (bibliotheques
d'illustrations flat-design reutilisables, animees a la main/After Effects), PAS en generation
video IA — MiniMax H3 (notre outil de generation video le plus recent) n'est PAS l'outil pertinent
pour ce registre precis. Le bon outil chez nous pour ce type de scene est le pipeline
stick-figure/personnage-vivant-SVG (R&D close 2026-07-29, socle complet, cf
PERSONNAGE-VIVANT-INDEX.md) — deja construit, deja valide, pas H3.

**Comment appliquer** : avant de lancer un appel de generation video IA (H3, Kling, Seedance...)
sur une scene a personnages, se demander explicitement "quel est le registre visuel de la
reference ?". Si la reference releve du flat-design / motion design vectoriel corporate
(silhouettes simples, aplats de couleur, style icone/pictogramme anime) → pipeline
stick-figure/personnage-vivant-SVG maison. Si la reference releve du photorealisme/incarnation
humaine riche (visages, texture peau, eclairage cinema) → generation video IA (H3/Kling) reste
pertinent, comme prouve sur NorthShield V3 (incarnation MiniMax H3 + mecanisme SVG existant,
valide 2026-08-08). Le critere de choix n'est pas "quel outil est le plus recent/puissant" mais
"quel registre visuel la reference impose".

cas reel — coherent avec la doctrine du projet "documenter une methode prouvee AVANT de la
generaliser". A garder comme repere, pas comme regle durcie tant qu'un 2e cas ne l'a pas confirmee.
