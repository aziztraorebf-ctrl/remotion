Deux méthodes validées explicitement par Aziz pendant la production du SVG-insert franc CFA (War-Map Sahel
AES, 2026-06-27), à appliquer systématiquement sur tout futur chantier SVG agentique.

**1. Mix-and-match SVG entre variantes non retenues**
Le SVG est du code éditable — ne jamais jeter les variantes générées mais non choisies. Une fois une direction
retenue, relire les autres variantes (même si un autre modèle/registre) pour repérer des éléments à greffer
(copier le `<g>`). Claude peut aussi écrire sa propre version SVG « maison », gratuite (0 appel API) : un SVG
codé par Claude sort déjà en groupes nommés propres, donc animable par construction — ce que Gemini/GPT ratent
parfois (SVG plat, non structuré). Citation Aziz : *« le mix est excellent, il garde la composition qu'on a
choisie, rajoute des éléments qu'on n'aurait pas pensé. »*

**2. Chorégraphie d'animation livrée AVEC l'image-cible, pas après**
Au point de contrôle Phase 1 (présentation des cibles SVG), toujours joindre la chorégraphie d'animation
détaillée (séquence timée, colorisation par segment, respect de la règle 5-6s, micro-mouvements vs gestes
explicites) — jamais l'image figée seule. Raison donnée par Aziz : ça permet de juger le MOUVEMENT avant le
code et d'éviter des itérations coûteuses en Phase 2.

**Comment appliquer** : les deux règles sont gravées en détail (avec méthode complète) dans
`memory/doctrines/PRODUCTION-AGENTIQUE-SVG.md` (sections "PHASE 1bis — mix-and-match" et "PHASE 1 = CIBLE +
CHORÉGRAPHIE"). Ce fichier est le pointeur rapide pour se souvenir que ces 2 règles existent et sont fortes.
