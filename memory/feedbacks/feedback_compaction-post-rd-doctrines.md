Le premier jet d'une doctrine issue d'analyse R&D multi-sources (chaînes tierces, breakdown vision, lecture de
script) est systématiquement trop dense — traiter ce premier jet comme un brouillon, jamais comme le livrable
final. Programmer une passe de compaction avant de considérer le travail terminé.

**Why:** Session 2026-07-02 (analyse Infographics Show + SimpleHistory + Hypothetically, 8 vidéos) a produit
3 doctrines totalisant 565 lignes en premier jet. Aziz a explicitement demandé une passe de compaction avec
le motif « trop dense, éviter le bruit inutile » — les 3 fichiers sont retombés à 157 lignes cumulées (-72%)
sans perte de substance : ne restaient que les tableaux de preuve/citations/frames-sources, pas les règles
elles-mêmes. Le volume n'est pas la valeur — plus une doctrine est longue, moins elle est relue sérieusement
la fois suivante.

**How to apply:** Après toute session d'analyse de références externes (chaînes YouTube, concurrents, corpus
tiers) qui produit une ou plusieurs doctrines : avant de les déclarer terminées, relire chaque fichier avec un
œil impitoyable et retirer tout ce qui ne change pas une décision de production (tableaux de citations/preuves,
répétitions inter-fichiers, bon sens déjà su). Garder uniquement les règles actionnables + le pourquoi minimal,
en pointant vers les frames/scripts sources pour qui veut le détail complet plutôt que de tout inliner.
