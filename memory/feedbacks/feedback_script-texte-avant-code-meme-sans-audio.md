Meme quand un projet ne va pas (encore) jusqu'a la generation audio, ecrire le SCRIPT TEXTE
(ce qu'une voix off dirait, phrase par phrase) AVANT de coder les panneaux visuels — pas juste
partir d'un breakdown visuel (structure/timing/couleurs) sans jamais verbaliser le sens.

**Pourquoi** : vecu sur le test MOCH-IT (reproduction/depassement d'une pub Fiverr, 2026-08-08).
Code directement depuis un breakdown visuel 3-modeles (Gemini/GPT/Kimi) sans script -> chaque
panneau illustrait un mot-cle isole, mais aucun fil de sens ne les reliait. Retour Aziz : "je ne
comprends pas ce que ca represente" sur plusieurs panneaux. Une fois le script texte redige a
POSTERIORI (6 phrases, meme structure narrative que la reference : probleme -> faux diagnostic ->
vrai diagnostic -> solution -> benefice -> CTA) et chaque panneau confronte a la phrase precise
qu'il doit servir, les corrections suivantes sont devenues plus faciles a juger et plus justes.

**Comment appliquer** : des qu'un projet reproduit/adapte une reference narrative (pub, explainer,
sequence a message), rediger le script AVANT le storyboard visuel, meme provisoire, meme si
l'audio n'est prevu qu'en toute fin de pipeline. Le script sert de colonne vertebrale de sens des
la phase de code — chaque panneau doit pouvoir repondre "quelle phrase precise est-ce que je sers ?"
Voir aussi [[fideles-mais-dependant-executer-pas-ajouter]] pour la discipline sur la FORME une fois
le script en place.
